# Сервис назначения ревьюеров для Pull Request'ов

Микросервис для автоматического назначения ревьюеров на Pull Request'ы. Есть управление командами и участниками. Написан на Go, БД - PostgreSQL. Все операции через REST API.

## Описание

Сервис автоматизирует назначение ревьюеров на Pull Request'ы в команде. При создании PR автоматически выбираются активные ревьюеры из команды автора (сам автор исключается). Можно переназначать ревьюеров, управлять командами и пользователями, получать список PR'ов, назначенных конкретному пользователю.

### Основные возможности

- **Автоматическое назначение ревьюеров** - при создании PR автоматически назначаются до двух активных ревьюеров из команды автора
- **Переназначение ревьюеров** - можно заменить одного ревьювера на случайного активного участника из той же команды
- **Управление командами** - создание и управление командами разработки
- **Управление пользователями** - добавление пользователей в команды, управление их активностью
- **Защита от изменений** - после merge PR изменение состава ревьюверов запрещено
- **Идемпотентность** - операция merge идемпотентна, повторный вызов не приводит к ошибке

### Модель данных

**Пользователь (User)** - участник команды с уникальным ID, именем и флагом активности `isActive`.

**Команда (Team)** - группа пользователей с уникальным именем.

**Pull Request (PR)** - сущность с ID, названием, автором, статусом `OPEN|MERGED` и списком назначенных ревьюверов (до 2).

## API

API описано в `openapi.yml`. Код клиента и сервера генерируется автоматически из этой спецификации через `oapi-codegen`.

Основные эндпоинты:
- Управление командами - создание, получение информации о команде
- Управление пользователями - добавление в команды, получение списка PR для ревью
- Управление Pull Request'ами - создание, получение, переназначение ревьюверов, merge

## Реализация и технические решения

### Архитектура

Проект разделён на слои:
- API слой - обработка HTTP запросов, валидация
- Service слой - бизнес-логика
- Storage слой - работа с БД

### Генерация кода из OpenAPI

Чтобы ускорить разработку и не расходиться со спецификацией, использую генерацию кода из `openapi.yml` через `oapi-codegen`. Автоматически получаю типы, валидацию и обработчики запросов.

### Обработка ошибок

В OpenAPI спецификации не все возможные коды ошибок определены. Если отправлен неверный запрос, возвращаю HTTP 400 с кодом ошибки `NOT_FOUND`. Планирую добавить новые коды ошибок в спецификацию.

### Оптимизация запросов

Метод `GetPullRequestsByReviewer` реализован с множественными запросами в БД - для каждого PR пользователя делаю отдельный запрос. Производительность достаточна, подтвердили нагрузочные тесты. Можно оптимизировать через JOIN запросы.

### Обработка граничных случаев

Если создаёшь команду с пользователями, которые уже привязаны к другой команде, возвращается ошибка 500. Планирую добавить более специфичные коды ошибок.
